# IMPLEMENTATION_PLAN — Investment Intelligence System

Основной источник требований: [INVESTMENT_ARCHITECTURE_PLAN.md](INVESTMENT_ARCHITECTURE_PLAN.md).
Этот файл фиксирует принятые технические решения, прогресс и оставшиеся задачи.
Краткое резюме улучшений (версии правил v1→v6, качество анализа, стоимость моделей): [RESULTS_SUMMARY.md](RESULTS_SUMMARY.md).

## Инварианты (не нарушать)

- Режим анализа только `manual`: никакой AI-аналитики по таймеру, при старте или по входящим котировкам.
- Независимая проверка гипотезы — hard gate: без успешного `hypothesis_critic` статус не может стать `ready_for_user`.
- Реальные торговые операции выключены. Есть только paper-брокер; `FinamTradeBroker` намеренно не реализован.
- Агенты не получают торговых секретов: дочерний процесс запускается с белым списком переменных окружения,
  в изолированной рабочей директории, только с evidence packet.
- Содержимое новостей/отчётов — данные, а не инструкции (явно сказано в промптах всех ролей).

## Калибровка Swing (2026-10-24)

Параметры подбирались **только на in-sample** (до 2025-12-09, та же граница, что у walk-forward); out-of-sample не использовался
при выборе. Сетка: цель 1.5–4 ATR, стоп 1.5–2.5 ATR, горизонт 10–20 дн., RSI max, окно пробоя, с откатами и без.

- С откатами ни одна комбинация не прибыльна на in-sample (лучшая −0.52%/сделку). Причина в сетапе, а не в уровнях.
- Предложены версии (статус `proposed`, активирует пользователь):
  - **v3** — только пробои, цель 2 ATR, стоп 2 ATR, горизонт 15. Выбрана по реалистичности цели, не по доходности.
  - **v4** — контроль подгонки: лучший in-sample вариант по доходности (цель 4 ATR).

| Версия | IS: сделок / нетто / PF / сверх индекса | OOS: сделок / нетто / PF / сверх индекса | Цель достигнута IS → OOS |
| --- | --- | --- | --- |
| v1 (active) | 256 / −0.90% / 0.62 / −1.25% | 212 / +0.46% / 1.22 / −1.42% | 9% → 16% |
| v2 (ретро: горизонт 12) | 238 / −1.11% / 0.60 / −1.43% | 189 / +0.94% / 1.43 / −1.33% | — |
| **v3** | 93 / +0.04% / 1.02 / −1.08% | 110 / +1.55% / 1.91 / −0.90% | 41% → 55% |
| v4 | 84 / +0.23% / 1.10 / −1.39% | 91 / +2.41% / 2.29 / −0.80% | 12% → 19% |

Выводы: v3 и v4 лучше v1 в обоих периодах; рост всех версий на OOS — в основном смена режима рынка (v1 тоже вырос).
**Ни одна версия не обгоняет индекс** (сверх индекса отрицательно везде): на этих данных buy-and-hold IMOEX лучше.
Рекомендация: v3 (цель достижима, улучшение устойчиво в обоих периодах); v4 даёт больше на OOS, но сохраняет проблему
v1 — большинство выходов по времени. Данные синтетические (mock): выводы о реальном рынке не переносятся.

### Активация v3 и прогон (gpt-5.6-luna, low)

- v3 активирована, v1 → `retired`. Прогон SBER/MGNT/YDEX: 43 с; MGNT и YDEX (откаты) отсеяны скринингом без вызова агентов;
  SBER (пробой) → критик `disputed`, кодовая валидация не пройдена: «прибыль/риск 1.00 < 1.2».
- **Конфликт:** у v3 цель = стоп = 2 ATR, а валидация требует R/R ≥ 1.2 — любая гипотеза v3 автоматически уходит в `needs_review`.
  Варианты с R/R ≥ 1.2 (цель 2.4–2.5 ATR) хуже v3 на in-sample (нетто −0.24…−0.19%) и лучше только на OOS — выбирать их по OOS = утечка.
  Предлагаемое решение (ждёт решения пользователя): сделать порог `minRewardRisk` частью версии правил (по умолчанию 1.2),
  выпустить v5 = v3 + `minRewardRisk` 1.0 — ожидание положительное за счёт частоты целей (IS 41% vs стоп 33%).

### v5 = v3 + `minRewardRisk` 1.0 (активна)

- Walk-forward: v5 точно повторяет прежнюю v3 (IS 93 сделки, +0.04%, PF 1.02 → OOS 110, +1.55%, PF 1.91, сверх индекса −0.90%) —
  изменился только порог. v3 при пороге по умолчанию теперь даёт 0 сделок (то, чем она фактически была); v1 без изменений.
- v5 активирована (v3 → `retired`). Прогоны SBER/MGNT/YDEX на gpt-5.6-luna: ~43 с; MGNT/YDEX (откаты) отсеяны скринингом;
  SBER — валидация пройдена, критик `disputed` (R/R 1:1 до издержек, −1.42% сверх индекса, 14 сделок по SBER, старая отчётность)
  → `needs_review`. После D25 ложные замечания про RSI и «устаревшие данные» исчезли.

### Фильтр рыночного режима: v6 = v5 + `regimeSma` 50 (proposed, не активирована)

In-sample (до 2025-12-09), база v5, SMA ∈ {0, 20, 50, 100, 150, 200}:

| SMA | сделок | нетто | PF | сверх индекса |
| --- | --- | --- | --- | --- |
| 0 (v5) | 93 | +0.04% | 1.02 | −1.08% |
| 20 | 91 | +0.12% | 1.05 | −1.01% |
| **50** | 88 | +0.20% | 1.09 | −1.05% |
| 100 | 85 | −0.20% | 0.92 | −1.23% |
| 150 | 78 | +0.14% | 1.06 | −1.35% |
| 200 | 75 | +0.16% | 1.07 | −1.38% |

Walk-forward v5 → v6: IS +0.04% → +0.20% (PF 1.02 → 1.09); OOS +1.55% → +1.46% (PF 1.91 → 1.84), сверх индекса −0.90% → −0.92%.
На OOS индекс всё время выше своих SMA: фильтр не отсекает ни одной сделки (110 → 110) при любом N — проверить его на этих данных нельзя.
In-sample улучшение держится на ~5 отсечённых сделках. Вывод: результат неубедителен, v6 не активирована, активной остаётся v5.
Отставание от индекса фильтр не лечит: оно возникает на растущем рынке, где фильтр пропускает всё.

Position не калибровался: на in-sample 30–40 сделок и все варианты убыточны — подбор был бы подгонкой под шум.

- **Модель эмбеддингов**: используется локальный hashing-эмбеддер; смена модели требует переиндексации (`POST /api/memory/reindex`).
- **Codex sandbox `read-only` разрешает чтение диска**. Finam-секрет не передаётся в окружение агента,
  но физически лежит в `.env`. Его реальные права могут включать запись; адаптер вызывает только read endpoints.
  До подключения торговых полномочий нужна изоляция секретов отдельным процессом/пользователем ОС.
- Численные лимиты риска, комиссии и капитал — значения по умолчанию, редактируются в «Настройках».
