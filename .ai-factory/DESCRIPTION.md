# IIS — Investment Intelligence System

## Обзор

Локальная персональная система исследования акций MOEX: ручной запуск анализа, роли Codex-агентов
с обязательной независимой проверкой гипотез, история решений, RAG-память на pgvector, оценка исходов,
ретроспективы, версии правил стратегий и paper trading. **Не автотрейдер: реальные заявки брокеру не реализованы.**

Источник требований — [INVESTMENT_ARCHITECTURE_PLAN.md](../INVESTMENT_ARCHITECTURE_PLAN.md);
решения, прогресс и блокеры — [IMPLEMENTATION_PLAN.md](../IMPLEMENTATION_PLAN.md);
итоги калибровки — [RESULTS_SUMMARY.md](../RESULTS_SUMMARY.md).

## Ключевые возможности

- Ручное исследование (Swing / Position / обе, режим `why_not_buy`, анализ «на дату» в прошлом без утечки будущего).
- Цепочка: детерминированный скрининг → `market_researcher` → `hypothesis_analyst` → независимый `hypothesis_critic`
  (hard gate) → кодовая валидация → решение пользователя.
- Point-in-time evidence packet: котировки, индикаторы, бэктест активной версии правил, события, отчётность,
  сбалансированные по исходам ретроспективы из памяти.
- Оценка гипотез на горизонте (комиссия, спред, проскальзывание, бенчмарк IMOEX, контрфактические исходы),
  ретроспективы `outcome_reviewer`, предложения новых версий правил, walk-forward сравнение.
- Paper trading: заявка с серверной проверкой риска → отдельное подтверждение → симулированное исполнение.
- UI «research desk»: сворачиваемый сайдбар (⌘B), палитра ⌘K, три темы, поповеры и slideover-превью.

## Технологический стек

- **Язык:** TypeScript (strict)
- **Runtime и пакетный менеджер:** Bun (Nitro preset `bun`); Node 22+ только для Vue typecheck
- **Фреймворк:** Nuxt 4, Nitro
- **UI:** Nuxt UI v4 (Tailwind CSS v4), `UChart` на `@tanstack/charts`, иконки `@iconify-json/lucide`
- **База данных:** PostgreSQL 17 + pgvector (HNSW, cosine)
- **ORM:** Drizzle ORM через NuxtHub DB (`@nuxthub/db`), миграции `nuxt db generate`
- **Кэш и состояние:** Redis — отдельные инстансы cache (allkeys-lru) и state (noeviction, AOF)
- **Аутентификация:** better-auth (email + пароль, сессии в Redis)
- **Валидация:** zod v4 (общие схемы в `shared/`)
- **Очереди:** BullMQ (служебные задачи; анализ в очередь не ставится)
- **AI:** провайдеры `codex exec`, `claude -p` и детерминированный `mock`; runtimeConfig по умолчанию использует `mock`, модель задаётся настройками
- **Рыночные данные:** Finam Trade API v1 (read-only) или изолированный mock-адаптер
- **Тесты и качество:** Vitest, ESLint (`@nuxt/eslint`, stylistic), vue-tsc

## Архитектурные заметки

- Чистая доменная логика (`server/domain/**`) не импортирует Nuxt/Nitro и покрыта тестами; все числа
  (индикаторы, уровни, размер позиции, исходы) считает код, а не LLM.
- Сервисы (`server/services/**`) работают с БД; API-хендлеры (`server/api/**`) тонкие:
  валидация → `requireUser` → сервис → ответ.
- Агенты — отдельные процессы в пустой временной директории, read-only sandbox, без пользовательского конфига
  Codex и без секретов в окружении (`agentEnv()`); роли — `.codex/agents/*.toml`.
- Независимость критика обеспечивается кодом: он получает собственный пакет и тезисы без уверенности аналитика,
  прошлые вердикты из памяти вырезаются.
- Изменения стратегий — только новые версии (`proposed`), активирует пользователь; прошлые гипотезы неизменны.
- Docker Compose — только локальная инфраструктура (Postgres :5442, Redis :6392/:6393).

## Нефункциональные требования

- **Режим анализа:** только `manual` — никакой AI-аналитики по таймеру, при старте или по входящим данным.
- **Безопасность:** приложение слушает `127.0.0.1`; каждый API требует пользователя; торговых секретов в системе нет;
  тексты источников — данные, а не инструкции (защита от prompt injection).
- **Логирование:** журнал запуска в `analysis_runs.log`, неизменяемый аудит в `hypothesis_events`;
  серверные ошибки — `console.error` без секретов.
- **Обработка ошибок:** `createError({ statusCode, statusMessage })` на сервере, toast через `useAction` на клиенте;
  сбой критика не роняет запуск — гипотеза остаётся в `awaiting_critic`.
- **Проверки после изменений:** `typecheck`, `typecheck:worker`, `test`, `lint`, `build`.

## Evidence-источники

Независимый ручной контур ЦБ: SOAP ключевой ставки, XML курсов валют, JSON M1/M2 и RSS
пресс-релизов. WSCO проверяет юридическую идентичность и загружает полные формы 101/102;
FinOrg сохраняет issuer-specific статус/лицензии с датой наблюдения. Неизвестное покрытие
остаётся `not_covered`, отсутствие записи не означает отзыв лицензии. Первичные документы PDF/XLSX/HTML —
ручной импорт с подтверждением фактов. Статусы, аудит, decimal-значения и версии хранятся
в PostgreSQL; source coverage и provenance входят в snapshots и кодовую проверку Position.
Проверки доступности и внешние блокеры: `docs/data-sources/availability.md`.

Проверенный ручной каталог первичных документов: PDF Яндекса/Норникеля и HTML формы 102
Сбербанка. Poppler извлекает текст локально; hash/page/row/unit проверки дают machine_verified,
отдельно от подтверждения пользователя. Применяются отраслевые критерии, fact-level периоды,
сравнения кварталов/YTD/годов и явная граница non-IFRS. Запуск Bun — scripts/start.ts.
