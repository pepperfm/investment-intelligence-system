# IIS — Investment Intelligence System

Локальная персональная система исследования акций MOEX: ручной запуск анализа, Codex-агенты с обязательной
независимой проверкой гипотез, история решений, RAG-память на pgvector, оценка исходов, ретроспективы и paper trading.
**Не автотрейдер: реальные заявки не реализованы.**

- Требования: [INVESTMENT_ARCHITECTURE_PLAN.md](INVESTMENT_ARCHITECTURE_PLAN.md)
- Решения, прогресс, блокеры: [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md)

## Быстрый старт (mock-режим, без ключей)

```sh
bun install
bun run services:up      # Postgres+pgvector :5442, Redis cache :6392, state :6393
bun run db:migrate
bun run dev              # http://localhost:3000 (слушает 127.0.0.1)
```

1. Зарегистрируйтесь на `/login` (локальный пользователь).
2. «Обзор» → «Обновить данные» (синтетические котировки, события, отчётность).
3. «Исследования» → выберите инструменты и стратегии. Для мгновенной ретро-оценки укажите дату в прошлом.
4. Карточка гипотезы → решение → (для одобренной long-идеи) paper-заявка → подтверждение.
5. «Оценки и ретро» → «Оценить созревшие гипотезы»; «Стратегии» → бэктест, предложение версии, walk-forward.

без секретов в окружении.

### Реальные данные Finam

`NUXT_MARKET_PROVIDER=finam` использует серверный REST-адаптер: каталог с пагинацией,
спецификации лотов, завершённые дневные свечи и чтение счёта. Нужны
`NUXT_FINAM_READ_SECRET` и `NUXT_FINAM_ACCOUNT_ID`. Токен остаётся на сервере;
адаптер не выставляет и не отменяет заявки. `NUXT_FINAM_SYMBOLS` задаёт тикеры через запятую;
`IMOEX@MISX` добавляется автоматически. Пустое значение выбирает все активные акции MISX.

Для перехода с mock используйте отдельную БД и выполните в ней `bun run db:migrate`.
Не переиспользуйте синтетические свечи, новости, отчётность, ретроспективы и калибровку;
синхронизация откажется менять источник у уже сохранённых инструментов.
Локальный переход 2026-10-25 использует `iis_finam`; исходная БД `iis` и игнорируемый
`.env.mock` сохраняют предыдущий режим. Пользователи и настройки перенесены, исследования — нет.

### Новости и финансовая отчётность

Ручное обновление данных в Finam-режиме также загружает:

- RSS корпоративных новостей Finam.ru: заголовок, краткое описание, ссылка и дата публикации.
  Привязка к эмитенту — по тикеру и явным названиям; sentiment не придумывается.
- Годовые и квартальные таблицы МСФО Smart-Lab: прибыль, выручка, денежные потоки,
  активы, капитал, долг и банковские показатели при наличии. Денежные значения переводятся
  в рубли по явно указанным единицам; отсутствующие значения не заменяются нулями.

Smart-Lab — **вторичный источник**. Ссылка «Отчёт» ведёт на документ, указанный агрегатором,
«Таблица» — на страницу извлечения. PDF автоматически не читается и не сверяется с таблицей.
Не импортируются LTM и зависящие от котировок оценочные мультипликаторы.
Для компаний без RUB-таблиц и для других стандартов отчётности покрытие не гарантируется.

`issuer_reports.published_at` хранит дату отчёта (если источник даёт только день — конец дня по Москве),
`available_at` — время первого получения конкретной версии чисел. Изменение значений создаёт
новый snapshot; прошлые строки не переписываются. Для новостей учитывается `retrieved_at`.
Исторический анализ видит только уже наблюдавшиеся системой версии; импорт сегодня не делает
таблицы достоверным point-in-time источником за прошлые годы.

Публичные страницы кэшируются на 15 минут. RSS содержит лишь текущую ленту, а не архив за три года;
отсутствие новости в ней не означает отсутствия риска. Ошибки источников возвращаются в `sourceErrors`
и показываются при обновлении; успешная загрузка котировок не маскирует отсутствие отчётности.
Новости и отчёты сохраняются также в памяти с датой доступности. `hash` остаётся лексическим
feature hashing, не семантической моделью. Автоматический запуск AI по данным отсутствует.

После обновления кода примените миграции `bun run db:migrate` к выбранной базе, в том числе при возврате
к сохранённой mock-базе. Схема расширена полями времени доступности и ссылки на документ.

### Модели по ролям

Переменные `NUXT_CODEX_{RESEARCHER,ANALYST,CRITIC,REVIEWER}_{MODEL,EFFORT}` переопределяют
общие `NUXT_CODEX_MODEL` / `NUXT_CODEX_REASONING_EFFORT`. Пустые значения наследуют общую настройку.
Локально выбраны: researcher — `gpt-6-luna`/medium, analyst — `gpt-6.1-sol`/high,
critic — `gpt-6-astra`/high, reviewer — `gpt-6.1-sol`/medium. Модели показываются в настройках.
CLI health проверяет наличие исполняемого файла, а не доступ аккаунта к каждой модели.

### Резерв LLMost

В «Настройки → Агенты и данные» кнопки «Основной» и «LLMost · резерв» переключают профиль
без перезапуска. Настройка сохраняется в БД и действует на новые исследования и ручной повтор критика.
Уже запущенное исследование сохраняет провайдеров, записанных при его создании.
Профиль основной использует `NUXT_AI_PROVIDER` / `NUXT_AI_CRITIC_PROVIDER`.

Ключ LLMost хранится только в серверном `NUXT_LLMOST_API_KEY`; базовый URL —
`NUXT_LLMOST_BASE_URL=https://llmost.ru/api/v1`. Модели и effort задаются переменными
`NUXT_LLMOST_{RESEARCHER,ANALYST,CRITIC,REVIEWER}_{MODEL,EFFORT}`.
При первом добавлении ключа/моделей в `.env` перезапустите сервер; дальнейшее переключение профиля — одна кнопка.

Каталог LLMost проверен 2026-10-25: researcher — `openai/gpt-6-luna-20260922`/medium,
analyst и reviewer — `openai/gpt-6.1-sol-20260929`/high и medium,
critic — `openai/gpt-6-astra-20260903`/high. Каталог заявляет поддержку `reasoning_effort`
и структурированного JSON для этих моделей. Health и переключение проверяют каталог без генерации.

Каждая роль отправляет отдельный stateless запрос со строгой JSON Schema; результат проверяется zod.
Инструменты, окружение сервера и брокерские секреты в запрос не попадают. Критик получает прежний
независимый пакет. Ошибки, отказы и обрезанные ответы не обходят hard gate.
Автоматического перехода на платный резерв и автоматических повторов генерации нет:
переключите профиль и явно повторите нужное действие. Начатое исследование само не возобновляется.

### Оценка результатов

Симулятор исполняет гэп через стоп/цель по открытию, в том числе в день входа.
Для внутридневного лимитного входа максимум дневной свечи не доказывает достижение цели после входа.
Верхняя граница бэктеста исключающая: IS-сделки не используют свечи на границе OOS или после неё.
Повторное сравнение версий на одном OOS не превращает его в новую независимую проверку.

Все оценки гипотез — сценарные, включая одобренные идеи. Фактические paper-исполнения хранятся отдельно.
Paper market-заявка ждёт первую дневную свечу строго после подтверждения и использует её открытие
с учётом спреда/проскальзывания. Лимитная — только касание на последующей свече, без старого close.
На дневных данных исполнения не моделируют внутридневную очередь, ликвидность и частичные fills.

## Миграции

Миграции лежат в `server/db/migrations` и коммитятся. `bun run db:generate` нужен только после изменения схемы

## Технические заметки каркаса

Каркас — PepperFM Nuxt Starter 0.1.0, Nitro preset **bun**. Bun — runtime и менеджер пакетов; Node 22+ нужен для
Vue typecheck. `.env` создаётся локально и не коммитится; секрет авторизации — не короче 32 символов.

- Nuxt Security headers are enabled. Its in-memory rate limiter is disabled; auth has its own Redis-backed limiter. Review CSP and trusted proxies per deployment.
- Builds never modify the database; apply migrations with `bun run db:migrate`.
- Cache and durable state use separate Redis instances, not just different Redis databases. Cache may evict; sessions/queues use noeviction and AOF. URLs are read at runtime, not embedded into build artefacts.
- Auth sessions live in Redis (no DB fallback, no cookie cache). Clearing durable Redis signs users out. /api/me is server-protected and does not serialize tokens; device tokens are loaded client-side only for revocation. Email verification, password reset mail and OAuth credentials are deliberately not configured yet. Add those before a public launch.
- Run schedule:register once per deployment; do not register schedules inside HTTP handlers. The worker is a separate Bun process. A scheduler queues work but does not guarantee exact wall-clock execution under load. Add domain-level idempotency before using real side effects.

## Макро и первичные источники

Раздел **Макро и источники** (`/macro`) работает независимо от ключей Finam. Кнопка
«Обновить ЦБ» вручную загружает ключевую ставку, USD/EUR/CNY, денежную массу M1/M2
и пресс-релизы; AI-анализ не запускается. Состояния источников также видны в настройках.
Применение новой схемы локально: `bun run db:migrate` (миграции аддитивные).

На этой же странице можно импортировать законно полученный PDF/XLSX/HTML до 20 MB:
указать юридическое лицо, стандарт, консолидацию, период, публикацию и подтвердить
показатели с единицами и страницей/таблицей оригинала. Для произвольного файла числа вводятся и подтверждаются пользователем;
проверенный каталог ниже использует отдельные детерминированные экстракторы. Повторный идентичный импорт не создаёт копию, исправления
создают новую версию. Реальные документы не принимаются для mock-инструментов.

Дата получения в IIS не подменяется датой отчётного периода: новые данные не попадут
в анализ прошлого. Для Position long требуется проверенная отчётность и свежий
макроконтекст; отсутствие данных отправляет результат на проверку, даже при согласии критика.
Smart-Lab остаётся вторичным непроверенным источником. Банковские формы могут быть
не опубликованы, сетевой сбой не означает отзыв лицензии.

Проверенные URL, воспроизводимый smoke и ограничения: [доступность источников](docs/data-sources/availability.md).
Проверка сервисов без БД/секретов: `bun scripts/data-sources/smoke.ts`.


Кнопка «Загрузить проверенные отчёты» точечно получает оригиналы Яндекса/Норникеля и HTML
формы 102 Сбербанка. Их числа сверяются кодом, без LLM: hash PDF, страница, строка и единицы.
Нужен установленный Poppler (`brew install poppler`), путь — `NUXT_PDF_TEXT_BIN`.
Это `machine_verified`; ручное подтверждение пользователя остаётся отдельным режимом.
Смена оригинального PDF требует проверки экстрактора. Никакой массовый сбор не запускается.
На странице банка есть формы 101/102 за два периода и сведения FinOrg; это отдельное юрлицо,
а не консолидированная группа. Квартал, YTD, год и non-IFRS не смешиваются.

## Решение, прогноз и качество дневных данных

Новые гипотезы `decision_v2` разделяют рекомендацию (`long` / `no_trade`), обоснование,
типизированные причины и отдельный необязательный измеримый прогноз. Критик выносит два
независимых вердикта. Поддержка отказа от покупки не подтверждает прогноз падения или роста.
Уверенность — субъективная оценка качества свидетельств, не вероятность прибыли.
Старые записи помечены `legacy`; исходные тексты, числа и вердикты сохранены.

В списке гипотез можно отметить строки и скопировать Markdown/TXT с источниками и замечаниями
критика. Смена фильтра снимает выбор. В карточке есть исходный snapshot и отдельный журнал
бэктеста с входными рядами, hashes, правилами и сделками.

Каждый новый запуск закрепляет ID/номер версии, полный набор правил, hash и издержки.
Смена active-версии во время выполнения не меняет запуск. Историческая дата означает
ретроспективный эксперимент с выбранными правилами; версии mock и Finam независимы.

**Реальные исследовательские свечи MOEX ISS:** на странице исследований можно явно выбрать
«MOEX ISS · физические сессии · реконструкция». Перед ручным запуском выбранные бумаги и IMOEX
синхронизируются; дневной OHLCV каждого используемого периода сверяется с полной часовой историей.
Акции используют shares/TQBR, индекс — index/SNDX. Несогласованные даты остаются в карантине.
В раскрывающемся разделе источников видны диапазоны, время получения и причины расхождений.

Глобальный выбор — только явной настройкой и перезапуском приложения:

```dotenv
NUXT_MARKET_PROVIDER=finam
NUXT_RESEARCH_BARS_PROVIDER=moex_iss
NUXT_RESEARCH_BAR_POLICY=physical_session_v1
```

Настройки по умолчанию не меняются. Finam остаётся источником брокерских/account данных;
его неоднозначные D-bars не подменяются молча. Новая бар-политика имеет собственную версию
набора входных данных, закреплённые audit IDs и физические сессии вместо логических дней.
Старые правила, свечи и гипотезы не переписываются. Подтверждённые исторические сессии
2024–2026 учитываются по фактическому ряду, без догадок по дню недели. Будущий срок условный,
если опубликованное расписание/допуск не установлены.

**Пределы достоверности:** историческая публикация и корректировки MOEX неизвестны. Поэтому
это `research_usable_with_limits`, явно помеченная реконструкция, а не документально наблюдавшийся
в прошлом snapshot и не разрешение на long/paper. Данные вне используемого окна не блокируют
сигнал, но конфликт внутри обязательного окна блокирует его. IMOEX обязателен только при
`regimeSma > 0`; при `regimeSma = 0` это контекст. Недоступный необязательный IMOEX не
блокирует достоверный сетап акции: его momentum/сравнительная доходность становятся `null`,
а пакет и UI показывают причину. Общий `loadSignalInputs()` используется исследованием и API
инструментов. Явно выбранный другой источник/дата не используют старую кнопку скрининга:
она показывает «не рассчитано» до нового расчёта.

Реальный `kind=research` на TATN с неизменённой Swing v1 и `setup=true` прошёл все роли
локального Codex при недоступном необязательном индексе. Итог — `no_trade`, критик supported.
Это демонстрация работоспособности, не доказательство прибыльности. Контроль с обязательным
индексом остановлен до агентов. [Новая приёмка](docs/market-data/research-benchmark-paper-acceptance-2026-10-26.json).

`blocked_by_data_quality` отделяется от отсутствия сетапа. Временная проблема цены переводит
paper-заявку в `suspended_data_quality`; возобновление только вручную с новым risk/critic gate,
без исполнения по старому бару. Реконструкция не исполняет заявки.

[Контракт и доказательства](docs/market-data-contract.md), [календарь](docs/market-calendar.md),
[фактическая приёмка](docs/market-data/acceptance.json).

«Оценить созревшие» выполняет только детерминированный расчёт. Он добавляет версию
`scenario-decision-v3-nullable-benchmark`, не переписывает старую оценку/гипотезу и не вызывает AI.
Условная покупка и оценка отказа (деньги 0%, избежанный убыток, упущенный рост) показаны
отдельно. Неполный/неоднозначный исход не маскируется нулевой доходностью.
AI-разбор завершённой оценки запускается отдельной кнопкой «Разобрать исход · AI».
Все paper-покупки требуют long-гипотезы, поддерживающего критика, успешной валидации
и одобрения пользователя. Для real paper дополнительно нужен независимо принятый источник
наблюдаемых после подтверждения bid/ask с ограничением возраста, board и подтверждённой сессией.
Такого контракта пока нет: `not_ready_for_paper_execution`, заявка приостанавливается; дневная
свеча даже с research-статусом verified не разрешает fill. Mock явно отделён как replay.
Реальных брокерских заявок нет.
